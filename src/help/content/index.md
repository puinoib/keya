Keya stores API keys and tokens in encrypted `.keya` files inside a folder you choose. There is no account system and no application backend: your cloud drive may synchronize the folder, and apart from the site analytics described in [Security](/docs/security), nothing leaves the device except the provider requests you approve.

AI providers are the default focus, but Keya is not limited to them. Search, scraping, email, payments, cloud, and internal API credentials fit the same model. Any service can be added as a custom provider with its own endpoint and check recipe.

Refreshing the page requires the master password again. Keya does not keep a warm session and does not store the password anywhere.

Use a current Chrome or Edge for the folder workflow. Other browsers can open and export a single `.keya` file, but they do not save edits automatically; see [FAQ](/docs/faq).
